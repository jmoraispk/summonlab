# Visuals

Wiki ID: `system.visuals`

Visuals own the stable, realistic presentation language shared by the Village, summons, heroes,
monsters, skills, equipment, training, and combat. They do not define mechanical power, morality,
personality, or rarity.

## Living Village

- one static Hearth composition with Summoning Gate, Training Court, and Tower Threshold;
- six manifest-bound adult human identities recognizable on every surface;
- a bounded runtime monster set with generator-ready race briefs;
- skill-effect and equipment assets tied to stable content IDs;
- summon and combat presentation as focused states within the three-screen flow;
- desktop and phone readability, reduced-motion behavior, and honest asset status.

The [Living Village plan](../milestones/living-village.md) defines the asset budget. The
[six-hero visual packet](../art/living-village-heroes.md) defines collision-safe identity slots and
required views. The
[monster gallery](../art/monster-gallery.md) contains current candidates; candidate images are not
automatically approved runtime assets.

The [monster database](../creatures/monsters/README.md) is the individual production/review surface:
one page per authored monster, with the identity reference first and five affinity
variants beneath it. The checked export converts production PNGs into compact web derivatives while
retaining source paths, hashes, versions, and review status.

## Deferred breadth

Culture/era packs, procedural anatomy breadth, settlement growth states, tower story environments,
neighbors, mounts, injury evolution, and the complete bestiary remain later work. All use the same
identity and provenance contracts rather than separate visual pipelines.
